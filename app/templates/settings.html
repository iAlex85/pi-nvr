Recording performance

The camera name/timestamp overlay burned into recordings requires decoding and re-encoding video (drawing text onto frames can't be done as a cheap stream copy) -- this is the single biggest driver of CPU load during recording, especially on a Pi 3 with no hardware video decode. Turning both off switches recording back to a near-zero-cost stream copy for every camera -- turning off only one still requires the same decode/encode pipeline for the other, so it won't save much on its own. Applies to all cameras; takes effect on each one's next recording restart (automatic -- no need to restart the service).

AI features (beta / preview)

Not yet implemented in this version. Continuous AI object/people/animal detection needs a neural-network inference engine running per camera, which a Raspberry Pi 3 genuinely can't do well without dedicated acceleration. These toggles just save your preference for a future update that adds real detection on more capable hardware (Pi 4/5 with a Coral/Hailo accelerator, or an x86 host) — enabling one right now has no effect.
